# teleop_web: Quest 3 WebXR teleoperation for the Unitree G1 (Dex1-1 grippers)

A browser page on the Meta Quest 3 (WebXR, three.js) and a Python server on the PC.
- The operator sees:
  - a see-through G1 that follows the robot's joint angles;
  - the head and wrist cameras;
  - a point cloud from the head depth camera;
  - "ghost" grippers on the controllers.
- Holding A / X makes that arm follow its ghost (IK). The trigger closes the gripper.
- The controllers vibrate at joint limits and on contact.

Sources (`server.py --source`):

| source | what it drives | DDS |
|---|---|---|
| `replay` (default) | recorded episodes, nothing live | none |
| `sim` | [unitree_sim_isaaclab](https://github.com/unitreerobotics/unitree_sim_isaaclab) with the patches in `sim_patches/` | domain 1 only |
| `real` | the real G1. **Untested on the robot; read `FIRST_ROBOT_TEST.md` first** | domain 0, explicit interface, typed confirmation |

## Layout
```
server.py         aiohttp HTTPS + WebSocket server (page, state, JPEG camera frames, point cloud)
sim_source.py     live control: ghost pose -> G1_29_ArmIK -> joint limiter -> arm controller; Dex1; haptics; clutch gate
real_source.py    the same on the real robot (domain 0, slower, startup gates, --dry-run)
cloud.py          depth frame -> pelvis-frame point cloud (voxel filter, tag-4 binary message)
web/              the Quest page (app.js, index.html, vendored three.js / urdf-loader / WebXR controller models)
robot_pc2/        head D435i depth publisher for the real robot's PC2 (README_PC2.md)
tools/            offline tests and helpers (test_live_offline.py, test_real_gates.py, test_grip_width.py,
                  test_input_sources.mjs, chess_reach.py / chess_place.py, ...)
sim_patches/      changes to unitree_sim_isaaclab (PATCHES.md)
xr_patches/       file needed from / changes to xr_teleoperate
chessreach/       reach map of the chess board (generated by tools/chess_place.py)
```

## Install (PC, Ubuntu)
1. Conda env `tv`:
   ```bash
   conda env create -f environment.yml
   conda activate tv
   ```
2. [unitree_sdk2_python](https://github.com/unitreerobotics/unitree_sdk2_python):
   ```bash
   pip install -e <checkout>
   ```
3. [xr_teleoperate](https://github.com/unitreerobotics/xr_teleoperate) at commit `817fb00c`, cloned to `~/xr_teleoperate`
   (or set `XR_TELEOP_DIR`):
   ```bash
   cp xr_patches/joint_limiter.py ~/xr_teleoperate/teleop/utils/
   pip install -e ~/xr_teleoperate/teleop/teleimager
   ```
4. G1 URDF with Dex1: `g1_29dof_mode_15_with_dex1_1.urdf` + `meshes/` from
   [unitree_ros](https://github.com/unitreerobotics/unitree_ros) `robots/g1_description`. Pass the folder with
   `--robot-dir` or `TELEOP_ROBOT_DIR` (default `~/projects/unitree_ros/robots/g1_description`).
5. TLS certificate (WebXR needs HTTPS). The server looks for `~/.config/xr_teleoperate/cert.pem` + `key.pem`, or pass
   `--cert/--key`. Never commit them:
   ```bash
   mkdir -p ~/.config/xr_teleoperate
   openssl req -x509 -nodes -days 365 -newkey rsa:2048 -subj "/CN=teleop" \
     -keyout ~/.config/xr_teleoperate/key.pem -out ~/.config/xr_teleoperate/cert.pem
   ```
6. Sim (only for `--source sim`): unitree_sim_isaaclab + `sim_patches/` (see `sim_patches/PATCHES.md`).

## Run
`run.sh` uses the `tv` env and writes `logs/server_<time>.log`. On the Quest, open `https://<PC-IP>:8443` and accept
the certificate.
```bash
bash run.sh                                   # replay (add --episodes-dir DIR)
```
Live sim:
1. Terminal 1, the sim (env `unitree_sim_env`):
   ```bash
   cd ~/VLA/unitree_sim_isaaclab && G1_REAL_HEAD_DEPTH=1 G1_REAL_HEAD_DEPTH_STRIDE=2 python sim_main.py --device cpu \
     --enable_cameras --task Isaac-Chess-Pieces-G129-Dex1-Joint-Factory --enable_dex1_dds --robot_type g129
   ```
2. Terminal 2, after the sim shows the robot:
   ```bash
   bash run.sh --source sim
   ```

Real robot, dry run first (sends nothing). See FIRST_ROBOT_TEST.md:
```bash
bash run.sh --source real --dry-run --i-understand-real-robot --arm-mode arm_sdk --network-interface <iface>
```

## Quest controllers
| input | action |
|---|---|
| A (right) / X (left), hold | that arm follows its ghost (refused if the ghost is > 25 cm from the hand) |
| trigger | close the gripper (opening = width slider) |
| grip, hold | wrist camera panel above the ghost |
| thumb rest touched, move | move the ghost relative to the controller (release = new offset) |
| thumb rest + reach for the bars | force / width sliders |
| B / Y | reset that ghost's offset |
| right stick right / left | start-stop episode timer / back |
| left stick up / down | next / previous episode (sim: scene reset, arms go home) |
| L3 alone | point cloud on / off |
| R3 alone | vibration on / off |
| both sticks pressed, move hands | move / turn / scale the scene (feet stay on the floor; hold grip for up / down); double press = reset |

## Safety (live modes)
- An arm moves only while A / X is held.
- Engaging is refused when the ghost is > 25 cm from the hand.
- No page data for 0.3 s: brake and hold.
- The controller starts by holding the current pose.
- Speed limits: sim 300 deg/s; real 90 deg/s, plus xr_teleoperate's 250 Hz clip.
- `--source sim` can only use DDS domain 1. Domain 0 is reachable only through `--source real`, which needs
  `--i-understand-real-robot`, `--network-interface`, `--arm-mode` and a typed `REAL ROBOT`.
